# Цель

Локальная система, которая весь день пишет лог моих действий, вечером задаёт мне вопросы по этому логу (текстом, не голосом) и собирает из ответов черновик дневника. Через несколько недель по накопленным ответам даёт персональные наблюдения и рекомендации.

**Готово, когда:** каждый вечер в дневной заметке появляются вопросы с фактами из лога, я отвечаю коротко, `/evening` собирает черновик дневника моим голосом, а раз в неделю приходят наблюдения, привязанные к фактам.

# Архитектура

```
сборщики (без LLM) → фильтр секретов (без LLM) → локальная LLM: саммари → вопросы в дневной заметке → мои ответы → /evening: черновик дневника
```

- **Сборщики:** ActivityWatch (окна, простой, URL), музыка через MPRIS (`playerctl`), транскрипты Claude Code (`~/.claude/projects/*.jsonl`), история терминала (atuin), git, позже переписки.
- **Фильтр секретов** работает детерминированно, до LLM: регулярки gitleaks/detect-secrets, чёрный список окон и приложений (менеджер паролей, банк, приватные вкладки, `.env`). Секреты отсеивает не модель.
- **Локальная LLM** сжимает лог: каждый час короткая выжимка, вечером из выжимок день.
- **Интервью:** 3–5 вопросов вписываются прямо в дневную заметку, к каждому факт из лога. Отвечаю асинхронно, можно коротко, можно пропустить. Энергию и настроение отмечаю одной цифрой 1–5.
- **`/evening`** (скилл того же ряда, что `today`/`week`/`month`): читает ответы, при необходимости задаёт пару уточнений в чате, пишет черновик от первого лица, сохраняя мои формулировки.
- **Рекомендации** раз в неделю, только со ссылкой на факты. Без морализаторства о продуктивности: день отдыха не считается провалом.

# Решения

- **Только текстовый ввод.** Голос не используется.
- **Чужие реплики в диалогах учитываются.** Саммари и вопросы опираются на обе стороны разговора (ИИ, переписки), не только на мои сообщения.
	- Следствие: содержание чужих сообщений попадает в саммари. Сырые логи хранятся только локально, вне хранилища и вне git, в зашифрованном виде, и удаляются через месяц.
	- В дневную заметку (она уходит в git-remote) чужие реплики попадают только пересказом по смыслу, без дословных цитат и без чужих контактных данных.
- **Разговор ведёт сильная модель** (Claude), но получает только очищенное саммари. Сырьё никогда не покидает машину.

| Сессия | GNOME на Wayland | стандартный оконный вотчер ActivityWatch под GNOME Wayland не видит активное окно, нужен вотчер через расширение GNOME Shell. Проверить первым делом |

**Бенчмарк `qwen3.5:9b-32k`:** 100 % на GPU, генерация ~15 токенов/с, чтение входа ~57 токенов/с, загрузка ~9 с. Думающий режим раздувает ответ до 2 минут, поэтому для саммари его отключать.

- Чтение входа медленное: часовые выжимки (вход 1–3 тыс. токенов) обрабатываются меньше минуты, а целый сырой день одним куском занял бы минуты. Отсюда двухпроходная схема.
- `qwen2.5-coder:32b` целиком в VRAM не влезет и пойдёт в основном на CPU, это очень медленно. Годится разве что для ночного прогона, и то вряд ли нужен.
- `bge-m3` уже есть: эмбеддинги для поиска закономерностей по ответам.

**Не установлено:** ActivityWatch, `playerctl`, atuin, gitleaks.

# Решено 2026-11-22

- **Код** живёт в отдельном репозитории `~/Projects/daylog` (заведён, локальный git без remote).
- **Сырые логи** хранятся 1 месяц, затем удаляются.
- **Стек: Python**, выбран по задаче, а не по навыкам:
	- официальный клиент ActivityWatch (`aw-client`) — Python;
	- готовые детекторы секретов и персональных данных (`detect-secrets`, Presidio) — Python, в JS/TS зрелых аналогов нет;
	- официальный клиент `ollama`, D-Bus/MPRIS, шифрование (`age`/`pyrage`), SQLite — всё из коробки;
	- проект — набор фоновых скриптов по таймеру, без UI и веб-сервера, где сильные стороны TS не нужны.
- **Вечернее интервью** проходит каждый день, включая воскресенье.
