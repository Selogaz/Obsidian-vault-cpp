Если опустить детали, то суть в следующем:

Нужно ответить на 2 вопроса: ветвится ли задача(меняются ли подпункты в зависимости от предыдущих) и будут ли в будущем ссылки на эту задачу.

Линейная задача, на которую не нужно ссылаться в других местах — task/multistep;
Линейная, нуждающаяся в ссылках — лучше short проект;
Нелинейная(ваш decision-tree) — single/longinform проект;

Нелинейная задача от линейной отличается наличием внутреннего состояния. Как вы реализуете его отслеживание зависит от предмета проекта. Лично я у себя наблюдаю где-то 6 вариаций отслеживания состояния:

1. Узел условия
Пример — мой недавний проект, где я отслеживаю лечение мигрени:
```
[!question]- Решение: продолжать сермион или идти к цефалгологу — 22.11.2026
**Наблюдаем:** число мигренозных дней в месяц + число приёмов суматриптана.
**Смотрим:** 22.11.2026, по окончании трёхмесячного курса.
**Ветки:**
   - < 4 мигренозных дней/мес и приступы не инвалидизирующие → закрываем проект, суматриптан по требованию
   - ≥ 4 дней/мес **или** приступы инвалидизирующие → запись к цефалгологу с дневником на руках
   - абузусный риск (суматриптан > 8–9 дней/мес) → к врачу немедленно, не дожидаясь даты
**Данные:** дневник головной боли в daily-заметках, сводка ниже в разделе «Наблюдения».

  - [ ] #task/waiting_for #category/health Свести дневник головной боли и принять решение по тактике 📅 2026-11-22
```
Этот узел — композиция, он работает только когда собран целиком.

2. Задача-будильник
Это задача, которая даёт старт узлу условия. Она обязательно должна быть с датой:
```
- [ ] #task/waiting_for #category/study Возобновить проект про вузы — после результатов ЕГЭ 📅 2027-07-01
```

3. Журнал развилок
Для удобства анализа держу принятые решения в отдельном блоке проекта. Тут, надеюсь, и без примера понятно.

4. Условие, найденное на ходу
Частный случай состояния: правило, которое выяснилось в процессе и меняет остаток работы. У меня это видно на примере проекта, где я настраивал синхронизацию Zotero и Obsidian:
```
[!warning] Не запускать постоянно
  `zotero_sync.py` + `.zotero_watcher.sh` — это **bootstrap** (Zotero→Obsidian). Постоянный запуск затрёт статусы Obsidian. Только для разовых массовых заливок.
```

5. Накопление наблюдений
Некоторые наблюдения требуют агрегации, т.к. рассыпаны по разным местам(например, по daily-заметкам). Я, например, агрегирую задачи в проекте следующим образом:
```
[!todo]- Дневник головной боли
  ```tasks
  tag includes #category/health
  description includes мигрень
  sort by due
  ```
```


6. Условие завершения проекта
В общем-то, необходимая часть любого более-менее длительного проекта:
```
**Закрыт, когда:** <наблюдаемое событие>
	**Разморозить, когда:** <наблюдаемое событие> — проверка 📅 <дата>
```

Ну и напоследок, узел условия должен быть понятен сходу, без контекста. Это еще одна отсылка к тому, что вся эта система призвана облегчать доступ и извлечение информации.
