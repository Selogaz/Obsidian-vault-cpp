Регулярная подготовка к техническим собеседованиям, пока стек будущей работы не определён. Опорная идея: **ядро + основной трек**, а не "только общие вопросы" и не точечно под вакансию. Трек берётся из [[годовой план карьерного развития]] – AI-инженерия на TypeScript.

> [!abstract] Диагноз после пробного интервью 22.10.2026
> Знания есть, ошибок по сути почти нет. Главная слабость – **слишком короткие ответы**: определение без механизма и примера звучит как зазубренное. Тест-дизайн – сильная сторона.

## Формула ответа

**Определение → почему / как работает → пример**, 30–60 секунд на ответ.

- Не знаю точно – "точно не помню, рассуждаю так…" и рассуждать вслух.
- Перечисления раскладывать по осям классификации, а не одним списком.
- В конце связать ответ с позицией
	- зачем это нужно на работе.

## Пропорция

| Блок | Доля | Почему |
|---|---:|---|
| Ядро | ~60% | Спрашивают на любой позиции |
| TypeScript-трек | ~40% | Под него нанимают, это реальный опыт последнего года |
| Java | 0% | Освежать только под конкретный оффер |

## Ядро

- [ ] **Самопрезентация**: рассказ о себе на 1–1,5 минуты, мотивация, истории проектов (поисковый движок, D&D-стартап с ИИ-мастером, автоматизация B2B-данных), ответ про зарплату, фильтр по локации.
- [ ] **Веб и сеть**: HTTP-методы и идемпотентность, коды ответов, REST, CORS, куки / сессии / JWT, путь от ввода URL до отрисовки страницы.
- [ ] **Данные**: SQL (`JOIN`, `GROUP BY` + `HAVING`, индексы, транзакции, [[java ACID|ACID]]), когда нужен NoSQL.
- [ ] **Инженерная база**: git (merge и rebase), Docker, CI/CD.
- [ ] **Тестирование**: пирамида, виды и уровни, тест-дизайн, моки.
- [ ] **Алгоритмы и проектирование**: O-нотация, базовые структуры данных, проектирование простого сервиса.

## TypeScript-трек

- [ ] **JS**: event loop, промисы и `async/await`, замыкания, `this`, прототипы.
- [ ] **TS**: структурная типизация, generics, union / narrowing, utility types.
- [ ] **Браузер и фреймворк**: рендеринг, React (состояние, эффекты, ререндеры), Next.js.
- [ ] **Node.js**: однопоточность, неблокирующий I/O, потоки.
- [ ] **AI-инженерия**: вызовы LLM, RAG, агенты и инструменты, evals.

## Ритм

2–3 сессии по 30–40 минут в неделю из блока "навыки / портфолио" годового плана, чтобы не выйти за потолок 35 ч/нед.

1. **Пробное интервью с Claude** – раз в неделю. Вопросы ядра и трека вперемешку, разбор каждого ответа по формуле выше.
2. **Тема недели** – одна строка из чек-листов выше: прочитать, проговорить вслух, ответить на 3–5 вопросов.
3. **Карточки** – каждый вопрос, на котором споткнулся, становится карточкой с префиксом `prog` в колоде `obsidian::programming`, начиная с [[формула ответа на собеседовании]]. Лицо – вопрос интервьюера, ответ – короткая суть, ниже развёрнутый ответ по формуле.
