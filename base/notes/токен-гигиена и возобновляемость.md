Правила расхода лимитов Claude Code (Pro/Max) и продолжения работы после обрыва сессии.

- **Одна задача = одна сессия.** Между задачами `/clear`: вся история сессии перечитывается моделью на каждом сообщении, мёртвый контекст жрёт лимит просто так.
- **Multi-agent воркфлоу не возобновляется в новой сессии**: resume работает только в той сессии, где воркфлоу запущен ([[особенности claude code workflows]]). Фраза «продолжи прошлый воркфлоу» в новой сессии бессильна — состояния прошлого рана в ней нет, всё стартует заново.
- **Замена воркфлоу-состоянию — чекпоинт-файлы в репозитории** плюс промт, который первым действием читает прогресс-файл. Так построен [[промт для возобновляемого ревью кода]]: после вылета по лимиту открываешь новую сессию и вставляешь тот же промт целиком — он сам продолжит с первого pending-пункта.
- **Универсальная фраза продолжения** (если возобновляемого промта под рукой нет):
> Прочитай {ПРОГРЕСС-ФАЙЛ} и продолжи с первого незавершённого пункта. Формат и правила — в шапке этого файла.
- **Предохранитель в любой длинный промт**: «сделай {N} шагов/батчей и остановись» — лимит не выжигается за один присест. На Pro: N = 3–4.
- **Multi-agent воркфлоу на Pro — только осознанно**: один запуск может стоить дневного лимита. Для ревью хватает батчей, для верификации — второй сессии.
- **Дорогое в контексте**: скриншоты, большие файлы, повторные чтения. Не проси перечитывать то, что уже в контексте; большие логи — в файл и grep по нему.
- **Если Sonnet буксует по кругу**: `/clear` → задача в plan mode → имплементация плана ([[если claude не справляется]]).
