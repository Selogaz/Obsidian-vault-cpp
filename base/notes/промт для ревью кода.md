Проведи глубокое ревью всего этого репозитория (dnd-frontend). Только ревью —
ничего не исправляй и не редактируй код.

Что искать:
1. Баги и логические ошибки — только реальные, с конкретным сценарием
	 воспроизведения, без спекулятивных «может быть».
2. Компоненты-переростки под декомпозицию: известны character/page.tsx (~700
	 строк) и StatsStep, но проверь всю базу.
3. Дублирование mobile/desktop-веток — где свести к одной адаптивной реализации.
4. Стаб-хуки, мёртвый и недописанный код.
5. Архитектурные слабости: границы слоёв, обработка ошибок, ретраи, кэши (svgCache).

Артефакт: файл docs/refactor-backlog.md в репозитории. Каждая запись:
проблема, файл:строка, почему важно, оценка усилия (S/M/L). Группировка по
приоритету: P1 баги → P2 быстрые победы → P3 крупные рефакторинги.

Прогони это как multi-agent воркфлоу с адверсариальной проверкой находок:
каждую находку независимый агент пытается опровергнуть, в backlog попадают
только подтверждённые. Ложное срабатывание хуже пропуска.
