# План: пиксель-аудит главной — 2 независимых анализа + судья

Главная местами заметно расходится с макетом (`107:6`), хотя посекционная пиксель-сверка 4.B
формально прогнана и закоммичена. Слепые зоны прежней методики (`session-prompts.md`, промпт 4.B):
посекционные Y-срезы не видят **стыков, межсекционных отступов и общего вертикального ритма**;
визуальное сравнение «мягкое» (средние расхождения нормализуются как «похоже»); инлайн-фиксы по
ходу сверки размывают картину. Повторять ту же методику бессмысленно — нужна другая.

## Схема: два независимых аналитика + судья

Аналитики различаются **методологией**, а не половинками страницы (у половинок общие слепые зоны;
независимость = разные failure-modes на одном и том же скоупе):

| Роль | Модель | Суть | Отчёт |
|---|---|---|---|
| Аудит A «Композиция» | Opus | top-down, взгляд дизайнера: силуэт страницы, стыки и межсекционные отступы, контейнер, иерархия H2, фоны/тёмность (канвас `#F4F4F4`), радиусы/свечения/фото | `docs/audits/audit-composition-1920.md` |
| Аудит B «Метрика» | Opus | bottom-up, линейка: значения из живой Figma (натуральные узлы `107:6`) против `getComputedStyle` на калиброванном вьюпорте; дельты, системные ошибки токенов | `docs/audits/audit-metrics-1920.md` |
| Судья | Fable | вердикт по каждой находке (совпадение независимых отчётов = сильный сигнал; спорное проверяет сам по первоисточнику), единый реестр, декомпозиция фиксов на Sonnet-сессии, вкусовые топ-дефекты чинит сам | `docs/audits/defects-1920.md` + фикс-промпты + юниты в ROADMAP |

A ловит гештальт, который B не измерит; B ловит системные сдвиги (не тот токен/кегль/вес),
которые глаз A нормализует.

## Правила независимости

- Оба аудита — **строго read-only** по коду (`git status` после — чист): фиксы только после судьи,
  иначе второй аудит и судья сверяют движущуюся мишень.
- Аналитики **не читают чужие отчёты** в `docs/audits/` (зашито в промпты).
- Запуск **последовательный, порядок любой** (оба держат `npm start`, порт 3000 общий).
- Известные расхождения (ROADMAP Этап 0 п.5/6/10/11/12, открытые юниты 4/14/18) помечаются
  `known:` и новыми находками не считаются.
- Промпты параметризованы `{ВЬЮПОРТ}`/`{УЗЕЛ}`: первый прогон — `1920` / `107:6`; мобайл
  (`320` / `317:10756`) можно прогнать теми же промптами позже. На обоих вьюпортах `1rem = 10px`.

## Порядок запуска (чеклист)

Промпты — в `session-prompts.md`, семейство «Пиксель-аудит» (теги `plan-pixel-audit.md`).

- [ ] 1. Сессия Opus → промпт «Аудит A „Композиция"» (`{ВЬЮПОРТ}=1920`, `{УЗЕЛ}=107:6`).
  Проверить: отчёт лёг в `docs/audits/audit-composition-1920.md`, таблица по всем секциям,
  код не тронут. Если схема отчёта неудобна — поправить промпт B до его запуска.
- [ ] 2. Сессия Opus → промпт «Аудит B „Метрика"» (те же параметры). Проверить:
  `docs/audits/audit-metrics-1920.md`, калибровка font-size зафиксирована, код не тронут.
- [ ] 3. Сессия Fable → промпт «Судья». Выход: реестр `docs/audits/defects-1920.md`,
  фикс-промпты в `session-prompts.md`, юниты добивки в ROADMAP (блок 4.D / п.4.7),
  вкусовые топ-дефекты починены самим судьёй.
- [ ] 4. Остальные фикс-сессии — Sonnet, по промптам судьи (порядок — по критичности из реестра).

**Мобильный раунд (320)** — опционален, решение по итогам десктопного судьи: системные фиксы
(токены/типографика/контейнер) чинят и мобилку, 320 уже проходила сверку 4.B-2, известные
мобильные баги — в техдолге Этапа 0. Если запускается: те же промпты A/B **отдельными** сессиями
(`{ВЬЮПОРТ}=320`, `{УЗЕЛ}=317:10756` — не совмещать с десктопом, полный обход и так забивает
контекст), судья — **Opus** по тому же промпту «Судья» (протокол к тому моменту откалиброван
десктопным раундом, реестр — `docs/audits/defects-320.md`).
